本建议绑定 `FORWARD_EVALUATOR_AUDIT.md` 中的两份原方案 canonical SHA。允许先实现固定计算内核和严格输入加载器，验收名称应为“内核工程验收”，来源适配与真实前向路径另列状态。当前可核实的官方历史同格式样本、字段语义、排序与下载范围能力不能全部改记为“未来尚未发生”。没有可信来源完整性验证器时，程序只允许部分结果和明确缺项，不产生 `NOT_TRIGGERED` 或 `FINAL`。

## 最小输入契约

| 输入 | 必需约束 |
|---|---|
| 原方案身份 | `plan_ref`、从 store 原 canonical bytes 复算的 `plan_hash`，严格匹配两份白名单；无任何覆盖数量、方向、窗口、费率网格的 caller 参数。 |
| 方法身份 | 新的固定 evaluator/schema/normalizer/coverage verifier 版本及源码哈希、真实创建/可得时点；旧方案尚未解析的 method refs 保持原状态。 |
| 两种截止 | `evaluation_information_as_of` 为本次允许使用信息的真实截止；`market_event_cutoff` 为行情事件截至，且不得越过原评价终点。二者均为带时区时间，统一 UTC，拒绝无时区输入。 |
| 来源原件清单 | 每个原文件的 SHA-256、字节数、允许的官方 URL、取得方法、实际取得时点、合约、数据角色、单位、官方请求/导出区间及边界语义、文件格式版本；本地实际 bytes 必须可复验，不能只相信清单字符串。 |
| 标准化事件 | 稳定 source-scoped event ID、原始行/记录定位、源文件哈希、合约、事件类型、事件时点、实际信息可得时点、官方顺序键；trade/mark/funding 各自数值字段为有限十进制，不接受 NaN/Infinity、负价、单位猜测。 |
| 完整性证据 | 来源适配器及固定 verifier 的身份、所核对的精确区间、原文件与标准化输出哈希、官方范围证据、缺口/歧义、可复算验证结论；独立回执绑定这些内容，不能只有自由文本或 `complete=true`。 |
| 前次状态 | `previous_review_ref`、从该不可变原件复算的 closing state hash、新 review 的 opening state hash；保存完整既有事件 ID/hash 集及来源清单、已覆盖区间、游标。 |

`source_sha256` 只证明字节身份，不能证明该文件包含交易所所有应有事件；文件中的最早/最晚时间也不证明中间没有缺行。固定 verifier 必须核实官方导出范围、文件/分页枚举和正常终止语义，并重新运行 decoder 或逐条核对原始记录。无官方保证时，不得凭 trade ID 连续性或“文件看起来够长”推断全覆盖。caller 提供的 receipt 即使哈希正确，也不自动成为独立证据；只接受已审查方法产生、身份可解析且绑定实际输入的验证结果。

覆盖必须分角色证明：入场/退出 trade 各自整个原定一分钟区间、实际持仓期间所有 funding settlement 事件、各 settlement 的精确 mark，以及按已声明官方采样语义提供的完整 mark 路径。不能拿成交覆盖替代资金费覆盖，也不能拿 OHLC 或最近 mark 替代原协议所需 tick/精确结算 mark。同时间多个 trade 没有可信先后则 `PATH_AMBIGUOUS`。已获取窗口未出现 trade 也须有完整范围证明，才可判无合法成交；缺文件是 `MISSING_DATA`。

## 时间与完整性边界

- 每个事件同时满足 `event_time <= market_event_cutoff`、`available_at/acquired_at <= evaluation_information_as_of`。后者应由取得原件时的真实回执约束，不以 event time 代替。一般还应要求 `market_event_cutoff <= evaluation_information_as_of`，不得审查尚未发生的行情。
- 后来取得的历史路径可在后来 review 中使用，但必须保存真实取得时间，明确是后来证据；不得倒签成先前 review 已知，也不得进入已冻结的事前信号。原信号始终为原 ZIP、原 settlement、原方向及预定入场时间下的年龄。
- 账本当前用单一 cutoff 同时检查事件与可得时间。新 wrapper 应先独立过滤/拒绝越过行情截止的事件，再使用本次信息截止回放，不能为了允许延迟下载而删除可得时间校验。
- 完整性是 evaluator 从各必要角色的证据推导出的结果，而非输入布尔值。未知 adapter、原 bytes 缺失、coverage 无法复验、精确 settlement mark 缺失，均不能产生 `FINAL`；终点已经到来不改变这一点。
- 固定情景可计算和实际净额可计算分别输出。12 个费率/滑点情景完整，仍不证明用户实际费用或实际成交滑点已知；原 `actual_net=null` 与原 FINAL 必要条件不得被维护版本放宽。

## 跨日和补数

1. 全前缀回放必须包含前次已有的全部事件，ID 相同则 canonical event hash 完全一致；不能仅检查本次恰好重现的交集。前次来源绑定、已确认覆盖和旧 state hash 同样必须校验，防止输入集缩短。
2. 原生效前状态只在确认零持仓、无成交、无事件后迁移。新状态注明迁移方法和原状态哈希；不能假造旧账本状态或把旧摘要当已有 cash ledger。初始化名义本金应依据原合法入场而确定，不为零收益方便编造初始金额。
3. 允许后获真实证据，但若新事件落在前次已经评价/确认覆盖的历史区间，必须形成明确的 review revision/supersedes 和 late-evidence reason；保留旧输出，不能伪称是普通追加后全部旧指标不变。已依赖旧结果的反馈需保留其原输入并标明后续修订。
4. 仅进入新的时间前缀时延续原持仓；午夜、每日 batch 截止和方法运行时间都不产生额外退出/重入。结算端点遵循原 `entry <= settlement < exit`，事件排序确定，所有情景同样去重。
5. 每步记录原始市场价、库存、已实现/未实现、累计资金费、双边费用/滑点以及完整权益序列。对原交易价单独扣滑点，或对调整后成交价计损益只能采用冻结公式，不能双扣。
6. 同一输入全路径单次回放与分日回放/补足前缀的最终状态及指标相等；第二次完全相同输入输出哈希相同。缺资料时不创建有利强平价或成本，不把“没有事件输入”当“没有发生事件”。

## 本轮合规交付边界

可以现在交付：固定计算内核、严格 loader、失败关闭的 unsupported/coverage-unverified 状态、官方同格式历史样本适配验证（若允许来源当前可得）、合成边界测试、独立检查和源码版本绑定。合成测试只能证明算法实现，不进入生产资料后备。

必须单列未完成：尚未验证的官方下载/解码和独立 coverage 能力、未来真实窗口的数据及原始 bytes、真实路径重放、自然触发身份、长期调度时区观察与经济效果。`WAITING_DATA` 必须带可辨识原因；当前 adapter 未实现与未来事件未发生应保持不同 reason code。
