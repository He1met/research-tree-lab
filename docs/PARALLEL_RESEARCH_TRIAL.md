# 双方向研究一周试行

政策版本：2026-09-26.v1。由用户批准，作为 planning/current 唯一规范的运行补充，不修改冻结研究规则、权限、原始规格或已封存结果。

## 首要交付及启动门槛

先完成一次真实数据 → 扣除成本的正式评价 → 反馈 → 网页展示。支持、否定均可；不要求盈利。BTC旧方案窗口已经结束，逐项记录 METHOD_REQUIRED / DATA_REQUIRED，不改规则或用合成结果填缺口。若不能取得其合法数据，保留原方案待数据，另选可依法取得数据、事前规则完整的方向完成真实流程。

正式评价器候选的公开祖先附件/字段泄漏须先修复、独立审查、冻结新版本并核实安装批准哈希。工程测试通过不代替独审。恢复旧任务、资料研究和诊断可先继续；这些不算一周试行开始。

启动门槛必须同时有：新方法独审通过和安装回执；一次已提交真实正式评价及成本依据；该评价的反馈引用；真实公开快照和回读证据。实际费用未知时不补零、不称成本已核实；假设费用情景不能替代本门槛。只有缺数复核不满足此门槛。门槛必须引用精确记录版本、hash和回执，不能仅写PASS。

## 两条路线的具体进入条件

- A：已准入不可变数据能够回答一个尚未完成的关键问题，且该问题所需成本、事件顺序和覆盖可核实；完整读取已有结果和在途认领，排除同证据重复。先固定问题、最小可证伪实验、基线、信息截止、失败/停止标准及数据hash，然后以独立request_key认领。现有BTC冻结方案继续原规则复核，不能改窗改规则作为A的新成果；无合格问题时保持WAITING_INPUT，选择其他合法产品，不强造实验。
- B：独立探索一个新机制及数据可得性，必须有真实原始来源、与既有研究实质差异和一个可被否定的问题。先排除已研究的资金费、库存、入场确认、公司行动、ADL等相同证据结论及当前在途问题；可研究实质不同的边界或新证据，但写明差异。其成果可以是机制被否定、数据不可得或明确的可检验提案，不强造经济评价。

当前两路线均为PREPARATION_ONLY；具体题目在启动时按实际Store和官方运行状态选择，不从旧聊天推定空闲。准备读取/方法诊断不生成假启动记录，也不重做已完成研究。

## 运行、所有权与计时

沿用四业务任务和验收heartbeat原实际频率、状态、权限及静默通知规则；不新建聊天、自动化或其他调度器。研究原生任务作为协调者，在门槛满足后使用官方并行子代理，统一gpt-6-astra/medium；发现任务只提出未重复问题，不另行启动A/B。每轮每路线一个关键问题，先做最小实验，有支持再深化；无新可行动证据保持安静。

每路线独立owner、request_key、专属输出及受控Store认领，读取共享不可变数据。同一问题被有效认领则复用/等待，不抢锁、不重复派发。长任务保存阶段产物和真实句柄；超时观察不是死亡证明。原生任务重入先查claim、实际运行状态及已提交run。发布仍只有既有发布职责执行。

实际研究启动记录由研究职责受控追加，绑定本政策版本、路线、唯一问题、claim、真实官方任务/代理身份、实际started_at、方法及数据版本。已退出的代理不能冒称仍并行。先启动一路时记STARTING；两路线均存在首次正式启动记录后，trial_started_at取二者started_at的较晚值，trial_ends_at严格为其后168小时。保留两条原始时间和引用，不倒签到授权、准备或恢复时间。两路线应由同一协调批次实际并行调度；无法并行时记启动障碍，不能用不同日期的顺序完成冒充并行。

`config/parallel_research_trial.json` 是当前控制状态，初始时间及引用为null。实际证据仍在稳定Store；配置仅由本实施/验收接续协调者从已验证原件更新，发布者只读。每次状态变更先新增独立回执至稳定本机operations目录，保留先前配置hash与记录引用，不覆盖历史回执。更新流程：PREPARATION_ONLY → READY（全门槛验证）→ STARTING → RUNNING → REVIEW_DUE → RETAIN_PARALLEL或RETURN_TO_SINGLE。任何环节证据不足保持原状态并记录原因，不靠到期或提示词升级。

试行到期由既有验收heartbeat处理，不睡眠守时。到期后不启动新的试行问题，允许已有工作完成并保存；不因此暂停原四任务、丢弃产物或强杀代理。结项选择只影响研究任务内的并行政策，不修改用户频率。

## 证据与一周评估

每个问题保存problem_key、路线、原假设/最小实验、证据版本、结论（支持/否定/数据不足/技术失败）、结果及复核引用、复用来源、重复拒绝原因，以及真实等待开始/结束事件。记录事实、原因解释和优化假设，不把同一结果的多个报告算多个问题。

由既有接续按以下口径汇总，并提供逐项原件引用：

1. 已解决问题数：满足事前完成标准并形成可核查支持/否定或确定的数据可行性结论的唯一problem_key数；尚待数据单列，不自动计解决。
2. 可复核成果数：有固定规则/方法、精确输入、完整结果和足够复算证据的唯一成果数；资料提案与经济评价分列，缺原件不计。
3. 重复工作：重复拒绝数、确认实际重复执行数及原因；复用资料/数据单列，不把拒绝计研究成果。
4. 等待时间：只从可信开始/结束事件计算每问题时长；没有可靠计时为UNKNOWN，右删失等待单列。不得从消息间隔、mtime、无任务记录或总历时推算研究用时。不同路线等待不得简单相加冒充节约的墙钟时间。

评估是否保留并行依据独立问题取得的实质增量、复核覆盖、重复/争用和可观察等待成本；缺可靠基线时明确不能量化提速。证据不足默认结束试行并返回单路推进，后续新证据可再评估；不无限延长一周、不以盈利或记录数量决定。将结项报告和控制状态持久化，原频率和正常研究继续。
