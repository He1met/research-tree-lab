# 日常运行与恢复

所有命令由官方应用在本项目中执行；用户无需手动开终端。项目没有模型 API 或外部行情 API 客户端，也不安装独立调度器。

四类任务先读 `STATE.md`、本机 `.local/installation.json` 与对应项目 Skill。安装配置保存稳定根、已核实唯一 remote、独立核验后的源码哈希；不通过临时 worktree 保存唯一证据。角色权限不足以构成 OS 沙箱，见 `INSTALLATION.md`。

1. 用 `python3 scripts/store_cli.py --help` 查询受控提交、认领、验证、批次和恢复入口。完整 manifest 出现后才参与正式评价。旧 ID 同内容幂等，异内容拒绝；不能以新 ID 重抽同一请求。
2. 研究读取已完整提交的复核/反馈，记录实际采用或不采用理由。每日复核冻结全部登记版本，保留跨日状态；最终评价必须到原终点且数据齐全。缺行情或费用保留未知，合成结果不得进入生产。
3. 发布执行 `python3 scripts/publish.py`。它复用已构建静态壳，只在新记录到来时生成快照。修改源码后的首次构建使用 `--build`，但正式推送仍要求独立审查过的源码哈希。
4. 发布执行 `python3 scripts/publish.py --push` 前核验配置中的唯一 remote 与 main 分支、源码审批哈希、完整性和公开范围。只自动提交 `site/`、`records/`，不会顺手提交源码改动。推送后仍须等待 Pages 成功，运行 `python3 scripts/verify_publication.py` 核对同一 snapshot、静态壳及所有对象，并实际打开网页核验；PUSHED 不等于已上线。
5. 发布中断只续传原 snapshot。不能重抽模型、替换研究结果、手改生成的净收益或修改 `web/src` 来插入新研究。
6. `python3 scripts/native_receipts.py` 仅回读四个已知原生任务的配置，更新本机回执与脱敏公开状态；不写原生配置或内部数据库，不重置用户频率。

研究原件在稳定 store，数据在稳定 data。公开静态镜像采用 `site/data/objects/<sha256>.json`，完整快照与 manifest 保存在 `site/data/snapshots/`。受限原件不公开，`LOCAL_ONLY` 不等于远端备份。历史快照保留旧版本与纠错前的时点，不能把未来数据加入过去。

恢复必须进入新的 `.local/restore-checks/<run-id>`，用保存的清单验证允许公开的文件、方法与计算。完整源数据尚未远端存档时必须单列，不以摘要替代原始证据。恢复目录不得递归进入归档。唯一原件、在途文件和被引用数据不得自动清理。

代码、评价器、schema、权限与依赖升级是独立维护版本。新结果不能靠降低规则通过验收；旧方法/旧方案继续可读、原规则继续复核。自然触发只能由官方运行身份确认，手动安全试跑、单元测试和合成浏览器场景分别记录。

首个公开恢复包见 GitHub Release `research-bootstrap-v1`，真实远端恢复回执为 `docs/remote-restore.json`。它包含 26 条当时已提交记录及 46 个允许公开的文件；后续新增记录的归档由发布职责继续处理。上游原始行情文件没有因此获得公开许可或完整远端备份。

Release 附件上传先使用当前官方浏览器支持的文件选择入口。若 Chrome 的 `fileChooser.setFiles` 因本地文件 URL 权限拒绝，当前应用还可通过已打开的 macOS 原生文件选择器选取同一份已核验公开包；本项目已实际成功，不必先扩大扩展或系统权限。仅操作已确认属于本任务的仓库窗口和附件，不改用户其他窗口。上传后分别记录附件公开可见、GitHub 显示的服务器摘要、实际下载字节与新目录恢复；前三者不能互相代证。浏览器策略拒绝时保留准确失败回执，不换 CLI/API、不更改安全设置、不绕过拦截。历史失败记录保留，后续成功另存回执。
