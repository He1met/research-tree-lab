## 方案摘要
在已经创建的全新项目中，搭建一个以文件为事实来源、React Flow为观察入口的自动策略研究库。系统自动探索不同机制、深入检验、保存当前条件下的候选方案，每日按原规则复核随后行情，并让反馈实际推动后继研究。历史结果由固定程序生成网页数据，不让AI逐次改页面。方案满足已核实的市场、规则和时效条件时突出标记，但不接账户、不下单。本方案同时定义数据、任务权限、研究方法、恢复与验收，目标是让一个人可以长期只观察、不接力管理。

## 2. 产品与架构：文件驱动，不是AI手工维护网页

```text
四类原生任务（官方应用中运行）
  方向发现 → 策略研究 → 原方案封存 → 每日独立复核 → 反馈 → 后继研究
                         │                            │
                         └──── 完整提交的记录 ────────┘
                                      ↓
                      校验 / 许可筛查 / 确定性索引生成
                                      ↓
                    公开记录、分片JSON快照、证据附件
                                      ↓
                 固定React Flow页面 → 浏览器读取同一快照
```

用户不需要开终端。安装依赖、构建、计算和Git由官方应用内已授权工具完成；这不是独立Codex CLI或脚本调用模型。项目不自建模型服务、业务API、数据库、消息队列或操作系统调度器。静态页面读取同源JSON文件不等于引入行情API。

建议实现：React + TypeScript + Vite + `@xyflow/react`；研究计算采用项目内少量Python模块。安装时核对实际兼容版本并提交锁文件，不写死未核实版本，不买Pro模板。原生HTML历史Demo只作阅读参考，不能冒充真实React Flow组件。[S03][S04]

## 3. 职责与运行数据根

一个主代码仓，多个独立研究输出目录。安装时由Codex取得实际路径，保存到不公开的 `.local/installation.json`：

- code_root：当前主项目目录，保存源码、规范、锁文件。
- store_root：稳定、非临时worktree的唯一研究原档根，可在主项目 `.local/store/` 下；默认不进Git。
- data_root：稳定共享数据根，可在 `.local/data/`；不把全历史复制到每个研究。
- release_ref：用于本次任务的代码/方法/依赖版本，不在运行中追随未审查源码。
- repository、pages_url：真实创建/核验后写入；未有值为null，不猜用户旧仓。

默认四个任务均绑定同一稳定本地项目；各自认领、独立写入。需要方法代码隔离时使用官方worktree，但将正式原件提交到获准的稳定store_root。官方worktree可能被清理，不能保存唯一证据。[S02]

## 4. 数据模型：研究轮次、方案、运行、复核是不同对象

| 对象 | 必要身份与关系 | 保存内容 |
|---|---|---|
| 产品/合约 | product_id、instrument_ref、spec_version | 用户意图、身份、数据角色、单位、规则来源 |
| 研究轮次 | round_id、parent_round_id、additional_sources | 问题、机制、深挖类型、实际进展；无父则独立根 |
| 方案 | plan_id/version、round_id、method_ref、dataset_refs | 一组完整可回放规则；同轮可有多方案与明确主选 |
| 执行尝试 | run_id、attempt_id、request_key | 实际开始/结束/阶段、代码、输入、日志、结果、错误 |
| 正式复核 | review_id、plan_ref、revision、cutoff | 阶段/最终/未触发/缺数、成本和权益、原规则回放 |
| 反馈/采用决定 | feedback_id、source_review_ref、decision_id | 事实、解释、待检验变化、采用/不采用/等待与后继 |
| 执行条件检查 | assessment_id、plan_ref、as_of、valid_until | 条件逐项证据、缺项与时效；不保存实际账户状态 |
| 发布快照 | snapshot_id、manifest、source_record_refs | 可重建公开投影与真实发布回执，不是第二套手写事实 |

每条记录有schema_version、实际创建与信息可得时间、来源、证据标识。图的parent_round_id是业务派生；React Flow的parentId只用于把P/R/F材料放入本轮容器，二者不可直接混用。[S03]

新增复核不改变研究代际；修改策略规则产生新plan版本，需要检验新问题时生成后继round。多来源合并只计一项研究，额外来源不变成复制成果。未开始的提案可显示但明确“待执行”。

## 5. 全部结果如何保存

### 5.1 原档目录（稳定store_root，私有于本机，不表示需要私有仓库）

```text
store/
  products/                         已核实的产品规格版本
  discoveries/<discovery_id>/        外部来源、缺口与提案
  rounds/<round_id>/                 本轮问题及身份
    round.json
    plans/<plan_id>/<version>/       plan.json、报告、代码/环境引用
    runs/<run_id>/<attempt_id>/      输入、事件、日志、结果、manifest
  reviews/<plan_id>/<review_id>/     原规则评价、跨日状态、反馈、manifest
  review_batches/<batch_id>/         全部纳入项与每项处置
  decisions/<decision_id>/           选择、反馈采用、休眠/重启
  readiness/<assessment_id>/         当前执行条件核验
  publications/<publication_id>/    导出/发布/回读/恢复回执
```

共享data_root保留原始下载与标准化数据版本，按来源/合约/周期/日期分区，方案引用精确清单和哈希。保存原始响应/文件、事件时间、可核实的发布/可得时间、实际取得时间。后来取得的历史数据不倒签为当时已知。

每份运行证据包含实际方案与代码身份、数据引用、分析输出、交易/信号事件、完整权益/库存、费用、相关日志及结论。资料研究可无交易文件，失败可无数值结果，但必须有真实终态与已有产物。不要把未知填0。

正式对象只追加。写入先在专属临时目录完成、校验引用和字节，再以完整manifest作为提交标志；未提交记录只用于执行观察，不参与正式结果评价。manifest可保存state=COMMITTED，失败执行也能完整提交错误证据。

同一request_key再次到来：返回已有执行、续接阶段或补归档；不得重抽模型/重做研究后伪装成同一次。相同ID不同内容进入冲突调查，不覆盖。

### 5.2 公开与长期保存

- Git：源码、当前规格、模型/方法模板、允许公开的紧凑记录、报告及全历史目录；保留版权与许可。
- GitHub Releases：允许公开的大文件、增量证据包和完整manifest。每批按真实新文件导出，不递归打包旧备份。
- 本机：共享热数据、在途文件、受限原件、未发布材料。未完成远端存档时明确`LOCAL_ONLY`或`ARCHIVE_PENDING`，不因写了链接便称已备份。
- 公开副本与原件分别记hash、大小和脱敏/排除说明；不能公开的原件显示原因、所在类别和备份状态，不暴露私人绝对路径。
- 仅用当前被授权的应用/连接功能上传。没有Release上传能力时报告具体缺项，不回退独立CLI或自建接口，也不以摘要冒充完整备份。

Git与Pages均有容量限制，不能用“全部历史可查”承诺所有大文件永远免费存储。[S05][S06][S07] 重复文件可按内容去重，但不同研究事件和负结果不合并删除。实验所引用的输入与恢复所需方法长期保留；仅可重建缓存可按安装时明确的清理规则轮转。

## 6. 网页如何自动显示新结果——不让AI每次插入组件

生产过程固定为：

1. 研究/复核任务生成结构化JSON与相关材料，调用已测试的文件提交逻辑。
2. 发布任务发现新的完整manifest，读取版本化原件，校验身份、单位、引用、时间、披露规则与纠错状态。
3. 程序生成允许公开的记录镜像和网页索引。AI可以写说明，不能直接重填收益、伪造状态或手工创建图节点。
4. 固定React Flow前端从`data/latest.json`找到一个不可变snapshot，再读取分产品/方向/日期的分片与按需详情。
5. 发布成功且实际打开确认后，另存receipt；尚未确认时只能显示已生成/已提交，不能自证未来发布成功。

建议公开投影：

```text
records/                             可公开的不可变记录镜像（Git）
web/src/                             固定前端模板（只在UI改动时修改）
docs/                                Pages静态产物
  index.html + assets/
  data/latest.json                    指向已完成快照
  data/snapshots/<id>/manifest.json
  data/snapshots/<id>/catalog.json
  data/objects/<content_hash>.json    可复用的历史详情/分片
```

同一静态壳可以连续使用；新研究正常只增加record与JSON投影，不改web/src、不复制粘贴HTML、不重新让AI设计布局。首次或源码变更才需要编译前端；日常数据发布复用已有静态壳。Pages会按配置发布静态文件，不在其上运行研究或模型。[S05][S08]

完整历史包含所有终态、在途索引、旧版本和纠错。前端默认只显示选择范围和已展开节点；搜索覆盖未加载的历史摘要并恢复祖先路径，不把隐藏后代画成新根。详情按需读取，不每次下载全部净值/行情。

从原档重建索引的结果在同一输入和生成器版本下必须一致。损坏的一项可进入显式异常目录并计入遗漏，不让全部研究停摆；缺失关键引用时不能伪装成完整关系。未知schema版本要明确标记，不静默丢字段。

发布顺序：对象→快照manifest→验证→切latest→原生Git发布→实际回读。只补发布，不重做市场研究。前端以一个snapshot整体切换；失败保留旧快照并标“最后记录”，不能混读不同版本。

浏览器刷新只读JSON。页面只能使旧标志降级过期，不能因刷新更新市场观察时间或把条件从未知升级齐备。公开浏览器时钟异常时显示无法确认时效。

## 7. 研究方法与成果：不能只有工程闭环

完整程序见RESEARCH_PROGRAM.md。研究同时支持四类目的：

- 独立新机制：来自官方材料、原始研究与新的市场信息，而非只修改旧失败策略。
- 深化/反证：成本、库存、暴露、少数事件、时段和参数稳健性等。
- 当前候选比较：在明确产品、期限、风险/暴露与成本口径内作选择，不按历史盈利排名机械决定。
- 数据/方法可行性：说明现有材料能回答和不能回答什么，不硬凑交易收益。

每项选题写明：问题、依据与反证、相对已有尝试的实质差别、基线、输入、完成标准、适用范围和下一动作。多因素设计允许，但须说明交互与归因边界；不穷举全部产品×参数×时间。

以预先定义的时间顺序验证、简单基线、成本压力和反例评价候选，研究阶段所有尝试记录数据暴露。简单规则、结构化选择与AI事件/文本增量在可比资源与信息截止下分别比较。没有增量就缩减该AI模块用途，不靠自信语言保留。

计划可包含未来路径和分阶段风险，不只预测某个终点涨跌。只有实际可估计时给概率/区间，并区分概率校准、未来收益分位与均值置信区间；P10不是最大损失。单个利润目标不是预期收益。

宽度和深度是任务选择的实际行为，不是显示矩阵或一个“AI分数”。源于新机制、深化、复现和修复的工作分别记录；为有价值且可执行的新方向安排真实机会，避免近期赢家永久霸占。资源不足时有理由延后与重检，不强制固定30/70比例。没有新信息时允许WAIT，不创建伪新研究。[S10][S11]

每个暂停分支有范围、理由和重启条件；同一证据下反复A→B→A必须识别。计划冻结以后，后继可以改规则，但旧方案按原规则继续复核。

## 8. 每日复核：全覆盖、增量、跨日连续

每日开始冻结全部已登记可回放方案清单和批次身份，晚于本批登记的下一批处理。包括旧版、不再主推、负结果、未触发与多候选，不只看当前主选。

- 使用方案合法生效后的完整路径，按原规则模拟，不是只比较两天收盘。
- 阶段结果保留模拟持仓、库存、累计费用和最后处理事件；不可每天重置或因为日报截止虚构退出。
- 结束且数据齐全：最终复核；仍在期内：阶段复核；未触发、到期未触发、缺数据、规则不全、路径歧义、技术失败分别表达。
- 已最终复核且无新增/纠正输入：复用，不每天算成新样本。新增数据或评价器纠错：新review revision，保留旧结果和反馈失效链。
- 费用未知保留null或明示情景；资金费按结算事件，网格包括完整库存权益。用更细数据或预先规则处理同K线顺序，不择优成交。[S09]
- 独立假设资金的方案收益不相加为系统利润。复核完整率、未成熟数、失败与缺数独立展示；重叠窗口/重复变体不是独立样本。

事实、原因解释、优化假设分离。研究读取已完整提交个项复核，不必等整个批次；反馈采用、检验、不采用、等待、因纠错失效均有记录。没有新复核不阻止独立探索。

如果策略中含未来LLM临场决定，必须在那些时点保存真实事前输出才能按实际决策复核；事后重新问模型不能还原当时决定。没有记录的动态规则不能由复核补写。

本地封存时点、公开可见时点和评估起点分开。仅本地时钟不能冒称第三方可信时间证明；没有可验证公開时点，标本地前向记录，不称公开事前预测。数据延迟或发布延迟超出方案要求，不再标“当前”。

## 9. “具备交易执行条件”突出标志

用户新增要求是展示标志，不是交易权限。使用精确名称：**具备交易执行条件 · 截至某时点**，同处显示证据阶段；说明不代表已验证盈利、保证成交、适合用户账户或已下单。

三个维度分别计算：
1. replay_eligibility：规则、数据与模拟口径是否足以回放。
2. evidence_stage / assessment：开发、历史验证、前向模拟；支持/否定/未知。
3. execution_readiness：真实目标合约与当前条件是否有足够证据支持执行条件标志。

不因历史净收益为正或AI自信直接升级。还未盈利但规则完整的方案可以登记复核，避免“先盈利才能发布、发布后才能复核”的循环前置。

| UI标志 | 判定要点 |
|---|---|
| 具备交易执行条件（醒目） | 目标合约规格核实、规则完整、执行方式可表达、数量/费用/路径模型明确、必要当前输入新鲜、触发截至观察时已成立、无已知失效/纠错、在有效窗口内；每项有来源/时间/方法证据 |
| 规则齐备 · 待触发 | 结构和必要当前信息齐备，但原先定义的触发未成立 |
| 可回放 · 执行待核实 | 可模拟，但只能取得历史、参考数据或缺必要当前执行事实 |
| 仅供研究 / 条件不完整 | 缺少可回放规则或基础材料；仍保留探索结果 |
| 已过期 / 已失效 | 原标志不再适用；保持历史原件 |

规则完整不意味着已核实该用户所在地区、账号模式或权限。项目不读取个人账户；标志详情明确`account_eligibility=NOT_ASSESSED`，不写“你现在一定能交易”。[S12]

标志依据有独立assessment记录，绑定确切plan版本、真实观察截止、各输入有效期、checks、evidence_refs和policy_version。valid_until不得晚于最早过期的必要输入或原计划新入场窗口；再发布不会续期。未知有效期、来源断链、原结果被纠错影响时不能保持醒目标志。

日后持有中的原模拟方案与新的入场就绪分开：新入场标志过期不替用户或原模拟自动平仓。一个轮次只有部分方案满足时，显示“1个方案条件齐备”，不能给所有候选通用标记。

条件检查由研究任务在有新输入时实际完成；发布任务调用固定逻辑校验/降级，不凭时间更新升格。现场数据不足时，该产品长期无醒目标志是可能的真实限制，不能靠调大有效期装成实时系统。

## 10. React Flow页面：保持已经确认的精简结构

顶部：产品、方向、搜索、仅看条件齐备、每日复核、简短新鲜度。产品从目录读，不写死代码。

主图：一轮一卡，左到右是代际，同代上下分叉；卡片显示中文标题、执行状态、方案/复核/下一步三行。醒目标志对应具体方案并可展开看缺项。

两种展开：
- 展开本轮：在本轮容器内以三个紧凑区域呈现方案、多日复核、反馈；不是每个附件一个主图节点。
- 展开后继：只控制派生子树，不干扰本轮展开。新一天复核不增加代际。

详情默认关闭；共用三个页签：研究方案、复核历史、反馈与下一步。过程/证据/ID/源码哈希折叠。每日复核使用同一抽屉，按日期/产品看批次与具体版本，点击定位到正确轮次。

保留未主推、失败、休眠、未触发和纠错；不显示覆盖矩阵、多库切换、故事播放、性能按钮、小地图、装饰流动连线或个人交易工具。背后的覆盖、快照和性能测试保留。

默认只画主派生线；额外来源在详情。多候选用显式selected_plan_ref选择摘要，无有效主选就分开列，不取第一项或收益最高项。历史版状态以当时已知信息展示，不把后来纠错解释提前灌入过去。

新数据不抢焦点、不自动fitView。记录筛选/展开/UI位置仅是浏览偏好，不改研究。按层级和方向加载，规模测试分总历史与可见节点，不承诺无限同时渲染。移动端抽屉可读、按钮有文字、键盘可操作。[S04]

## 11. 原生定时任务与权限

详见AUTOMATIONS.md及四份任务正文。首版采用四类职责，不是四套服务：方向发现、策略研究、每日独立复核、观察发布。当前建议时点可由用户随时调整。

原生任务真实可选项目目录、worktree、模型和能力取决于账号与版本。官方资料说明任务使用默认sandbox；不能把角色表冒充每任务自动拥有独立硬沙箱。[S01][S13]

权限必须分三层写回验收：
- 工作约定：任务只写自身产物，读旧原件；靠提示词不足以强制。
- 程序控制：路径白名单、所有权、manifest、发布验证、禁止覆盖；说明能拦截哪些入口，不能冒称能阻止拥有文件权限的任意代理写入。
- 实际环境：可用权限profile/文件权限与GitHub授权；测试越界写入和受限网络，记录是强制隔离还是仅协作约定。安装需用户登录/批准时只提出必要操作，不修改全局权限或其他项目。

复核任务需要保存结果，因此不是整个会话纯只读；目标是原方案只读、复核目录可写。只有发布任务需要本项目仓库写与允许的附件发布；发现/研究/复核默认不需要远端写权限。插件权限和本地文件权限是不同控制，不因允许GitHub写就开放Mac全盘。[S14]

无独立CLI/API回退、无内部任务数据库编辑、无假任务ID。先创建/回读/试跑，再记录自然时点；等待自然窗口不占锁睡眠，也不要求用户先手工完成多轮才允许自动化。自动恢复仅作用于确认的本项目对象；整体应用/网络/额度故障仍可能需要环境操作。

## 12. 可持续性：每个功能必须有持续数据来源和恢复路径

| 功能 | 持续输入与责任 | 异常/恢复 |
|---|---|---|
| 新方向 | 方向发现的真实来源与覆盖审查 | 无新来源不伪造；研究仍可处理其他问题 |
| 当前方案 | 研究的完整输入与方法记录 | 数据陈旧降级；不因发布阻塞而重跑 |
| 每日复核 | 完整登记清单、路径与跨日状态 | 部分失败可续，已结束无变化复用 |
| 后继树 | 显式父轮次与反馈采用 | 无父证据标未知，不猜、不复制 |
| 执行条件标志 | 独立checks+时效 | 自动过期；不能仅刷新时间变绿 |
| 历史详情 | 不可变原件及兼容读取器 | schema版本可回放；坏记录隔离并可见 |
| 网站更新 | 确定性索引和受控发布 | 发布失败保留旧快照；远端只有陈旧可见，不臆测Mac故障 |
| 长任务 | 实际阶段/进度/所有者 | 失联核实，不凭超时删锁；无外层控制能力如实报告 |
| 存储增长 | 共享数据/内容去重/分片/增量包 | 未备份项可见；不为省容量删唯一研究证据 |
| 升级 | 固定版本、测试、旧方法快照 | 新版仅影响新研究；渲染/算法/权限变更分开审查 |

固定进度检查不是统一强停。执行时间很长但有进展就继续；没有任何新工作时结束本次唤醒，不用无限循环代替调度。频率控制调用机会，不精确等于token预算；余额只能显示官方实际可见值，未知不估造。

模型可提出新方法、分析代码和可逆局部修复，经必要测试和独立检查后采用；不能在普通研究轮里重写公共schema、评价口径、权限、备份删除或安全策略以使自己通过。公共变化单独标方法/维护版本，保持原记录兼容。与任务数量限制无关。

不在每轮读取所有历史：短STATE指向精确索引，检索相关机制、负例和未消费反馈。每次输入记录哪些版本实际被看见；引用未读材料不算消费。恢复依赖文件，不依赖对话永远存在。

## 13. 从用户已建的新项目开始的交付次序

1. 读取当前项目实际文件与路径，识别已有修改。不要清空、覆盖或另建第二套项目；不扫描旧交易目录。
2. 建立总规格、产品意图、四Skills、数据契约、权限/能力表；不得把模板数据注册为生产。
3. 实现最薄的完整提交、引用校验、执行条件判定、每日复核状态和确定性publish投影；先用合成案例证明逻辑。
4. 实际安装并构建React Flow，按确认UI完成新研究→自动出现、复核→原轮更新、反馈→后继下一代；无实际库运行就标未验收。
5. 通过允许的来源并行开展四产品最小数据核验，至少保存一项真实研究，逐产品报告能研究的范围；不等全产品齐备才交付。
6. 用受控范围创建/关联公开仓库与Pages；先完成可公开小样本发布及真实回读。未完成不要给预期URL冒充已上线。
7. 在同一首版创建、回读、试跑并启用四项原生任务；没有权限/工具时完成其余工作并列一次性的准确界面操作。不给用户例行研究审批。
8. 后续自然窗口里形成原方案→按原规则复核→实际后继；与UI合成检查分开记录。没到期如实WAIT，不补假行情。
9. 发布任务执行恢复和兼容检查：从公开记录+允许证据恢复一项研究，重建前端，检查旧版哈希，记录未备份原件。不要承诺恢复未公开且没备份的材料。

验收是持续的：代码已完成、真实单轮通过、自然调度通过、研究效果得到支持分别记录，不能相互替代。用户只做第一次登录/权限设置及真正环境例外，日常不接力。

## 14. 本包如何使用

将本包放入刚建项目的独立 `planning/current/` 目录，避免覆盖当前AGENTS。向Codex发送 FIRST_MESSAGE.txt。由Codex对照本规范安装必要文件、四个任务与页面，而不是要求用户逐个手填JSON。

本包提供：总规格、研究程序、任务与权限、完整四任务提示词、Skills、产品意图模板、标志策略、合成文件示例、参考纯函数和验收清单。没有真实模型调用、行情连接、发布脚本或React Flow生产代码；这些由Codex在用户实际项目中实现并验证。

README和VALIDATION.md列实际文件检查结果。不得把参考测试通过称为原生任务已创建、交易方案有效、网站已上线。
